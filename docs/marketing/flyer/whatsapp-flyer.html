AI · Milvus

Intelligence layer

Where we use AI & Milvus wisely

Vectors assist; rules protect accuracy. Chat and upgrade analysis sit on top of graph truth—not instead of it.

Today — used where it adds signal

  • Milvus infra_interactions — store exhaustive Layer-1 interaction signatures (VPC, SG, CIDR, ports, HA facts) extracted from the graph.
  • Milvus infra_patterns — canonical pattern template vectors for similarity lookup.
  • Hybrid pattern derive — family / HA / port rules first; vectors confirm or suggest only when rules don’t match. Prevents “pretty but wrong” pattern stamps.
  • Milvus iac_patterns — IaC chunk embeddings for similar-repo / fleet pattern detection.
  • Release Compare AI — upgrade paths, restart/downtime hints, doc-aware notes; engineer chat scoped to Raise PR workbench.

Why this is “wise”

  • Graph (Neo4j) + Postgres remain source of truth for lineage, cost, and CAB evidence.
  • Milvus is a similarity index, not the authority for security or HA topology.
  • AI chat is bounded to release/PR context—not a free-floating chatbot inventing blast radius.

Future enhancements

  • Richer embeddings (real model vs local hash) for cross-org pattern search & duplicate-module detection.
  • Vector-assisted blast-radius ranking (“most similar past incidents / upgrades”).
  • Milvus-backed RAG over AWS/module docs inside Release Compare chat.
  • Natural-language ask across subscribed estate (“which apps still pin vpc < v3?”).
  • Automated remediation PRs grounded in graph + approved pattern stamps.
  • Continuous CVE / policy retrieval ranked by business blast radius.
